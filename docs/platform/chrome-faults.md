# The platform, as measured: Chrome faults

This file holds Chrome faults outside the capture result itself: a DevTools screencast gap after a handoff, and a renderer crash. It is part of [the platform measurements](../platform.md), which lists every item and the table conventions.

| <a id="item-13"></a>13 | **The DevTools screencast goes dark for ~250ms after a return handoff** — when the presenting WebGL canvas leaves the composite (opacity 0 or unmount, same either way), `Page.screencastFrame` emission stops for ~250ms while the graphics pipeline runs on: a trace of the same window shows compositor frames submitted and PRESENTED with gaps ≤17ms, forced composites (`Page.captureScreenshot`) show the page's animation advancing smoothly, and rAF + style writes never pause. Constant across headless/headed and CPU throttle 1×/6×; not reproduced by a minimal DOM+WebGL swap page, so the trigger sits somewhere in the full rig (capture sources present) and is not yet isolated. The screen never freezes — the *instrument channel* does. | <a id="item-35"></a>35 | **Chrome's renderer segfaults when `moveBefore` puts two `position: fixed` elements inside an absolutely positioned `container-type: inline-size` element and a `@font-face` rule arrives in the same task.** HTML-in-canvas is not involved: two plain fixed-position `div`s crash Chrome 153, 154, 155, 156 and 157 with no flags, and `insertBefore` does not. Munari meets it because its parked capture canvases are fixed-position elements that a Surface docks with a move. The crash is a null-pointer SIGSEGV in the renderer, shown as "Aw, Snap!" error code 11. On the overview, the wordmark parks six `layoutsubtree` canvases in `body`, calls `requestPaint()` on each, and a few milliseconds later moves them with `moveBefore` into its letters inside the page's size container. In most sessions the first load survives and every later load crashes, some variants crash on the first load too, and with the HTTP cache disabled repeat loads survived. When the moves happen does not separate the two: surviving first loads moved the canvases 100-336 ms after navigation, crashing loads 75-205 ms. Each of these stops the crash: removing `Element.prototype.moveBefore`, so the move falls back to `insertBefore`; using `insertBefore` for these canvases only; deferring their moves by one animation frame; making the container `position: static`; removing its `container-type`. These do not: turning `drawElementImage` into a no-op, removing `updateElementGeometry`, making `requestPaint` a no-op, removing `navigator.gpu` or the wordmark's WebGPU scene, dropping the letters' transform or the dock's `display: contents`, and removing everything on the page but the wordmark. The remaining ingredient is a font face that arrives in the same task as the moves. On the overview it came from the wordmark's Google Fonts stylesheet, which is why a static copy of the page did not crash. Two plain Surface parts reproduce it when a `@font-face` rule is added in the same task as the dock moves: every load crashes, the first included. Added one task later (`setTimeout(0)`), or as a plain rule instead of `@font-face`, it does not. The library now docks capture canvases with `insertBefore` (`insertRetained` in `retainedMove.ts`), which never crashed, and puts the held copy's CSS animations back at the live node's pose after the insert. The overview also keeps its size container on `main`, which does not hold the wordmark. The stack cannot be read, because Chrome's macOS framework ships without symbols. Reported as https://issues.chromium.org/issues/575560154. **Item 13 is a fact about the measuring rig, not the screen** — and it
is load-bearing for anyone instrumenting a crossing: a passive
screencast read of the first ~250ms after a return swap measures
nothing, and an instrument that trusts it will report a freeze that is
not there. `crossing-flash` read that window with forced composites
instead — each screenshot is the compositor's own output of the
committed state, clocked by the instrument rather than by damage. In
headed runs the same blindness skewed the cast's timestamps enough that
path-continuity over-read by ~3.5px at forward swaps, so that gate's
contract was the headless run. The gate itself was removed on
2026-08-15 (instruments/README.md); the recipe is the part worth
keeping, and it is this paragraph.
