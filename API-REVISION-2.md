## A basic handoff

```tsx
<SurfaceCanvas />

<Surface inScene={selected}>
  <Card />
</Surface>
```

`selected` is application state. `Card` is an application component. Munari mounts the content once, measures it, and supplies a flat mesh displaying its HTML. The mesh starts at the content's page position. Lifting, bending, and other effects require scene code.

`inScene` requests the handoff. `useSurfaceStatus()` reports:

- `requestedInScene`: the author's intent, including during native fallback.
- `presentation`: `page`, `scene`, or `null` before any presentation exists.
- `sceneReady`: the required sources and draws are prepared.
- `isTransitioning`: the handoff is progressing or waiting for preparation.
- `supported` and `reason`: capability/content support and an unavailable reason.

The presentation callback uses the same `page | scene | null` values. Motion
completion and string-valued driver targets use `page | scene`. The motion hook's
`position` and numeric target use raw 0..1 values. A scene animation may keep moving
after the handoff finishes; Flight keeps its canvas running until its physics stops.

One unnamed canvas is the default. For several hosts, use distinct IDs and an
explicit association. Reusable client examples can use React `useId`; independently
server-rendered roots need unique, matching `identifierPrefix` values during server
render and hydration, or explicit document-unique IDs. A scene-side Surface belongs
to its enclosing canvas and rejects a conflicting `canvas` prop.

A delayed or lost host keeps the HTML usable. Preparation stops claiming renderer
frames when missing input is the only possible progress. Development warns once
after ten seconds of an unresolved host or preparation wait, without changing state
or invoking `onError`. Declaring a scene before it is requested is valid and quiet.

## Compose a custom scene

```tsx
<Surface.Root inScene={selected} canvas="controls">
  <Surface.HTML>
    <ControlBoard values={values} setValues={setValues} />
  </Surface.HTML>

  <Surface.Scene>
    <Surface.Mesh alpha="source">
      <ControlsHardware />
    </Surface.Mesh>
  </Surface.Scene>
</Surface.Root>

<SurfaceCanvas id="controls">
  <ControlsLights />
</SurfaceCanvas>
```

`Surface.HTML` supplies the live content. `Surface.Mesh` displays that content in the scene. `ControlsHardware` is the demo's component for its physical controls, motion, shadow receiver, and named anchors. `ControlsLights` supplies the demo's lights. Neither is generated by Munari.

`Surface.Scene` can contain groups, movement components, shadows, other meshes, and custom renderers. It retains those children through preparation, return, and the draw that clears them. It contributes to a shared canvas; it does not create an isolated Three.js scene. Shared lights and cameras belong at canvas scope.

Whole-Surface status and motion hooks work under `Surface.Scene`. Texture and anchor hooks need the source selected by `Surface.Mesh`, or an explicit handle and part name. A separately authored R3F tree can use `<Surface.Scene surface={handle}>` inside its canvas.

Use `placement="match-dom"` for page alignment, or `placement="manual"` with authored geometry and scene coordinates. Geometry, materials, raycast behavior, and pointer policy stay on the mesh. Deform geometry through `deformSurfaceGeometry` when pointer targeting must follow the deformation.

[Controls](apps/lab/src/scenes/controls/Controls.tsx) and [Flight](apps/lab/src/scenes/flight/Flight.tsx) show complete callers. Flight keeps one Root per card so beginning a drag does not remount its content.

## Move the page destination without remounting content

```tsx
const target = usePageTarget()

return (
  <>
    <section>{!inRightColumn && <div ref={target.ref} />}</section>
    <section>{inRightColumn && <div ref={target.ref} />}</section>

    <Surface.Root inScene={dragging}>
      <Surface.HTML target={target}><Card /></Surface.HTML>
      <Surface.Scene><FlyingCard /></Surface.Scene>
    </Surface.Root>
  </>
)
```

`inRightColumn` and `dragging` are application state. `target` names the current
page slot; `Card` stays at one React position. The target ref moves its live DOM
before React removes the old slot. A missing target hides the page content;
reattaching restores it. Six real-browser moves preserved the original focused
input, its value, and its component's local counter state.

[Flight](apps/lab/src/scenes/flight/Flight.tsx) uses `createPageTarget()` once per
card because it manages a collection. One stable Root per card lives outside
the changing column lists. This is needed when moving a component between
parents; an ordinary handoff in one page slot needs no target.

## Update a shadow after its card moves

```tsx
function CardShadowSync({ shadow }) {
  useSurfaceBeforeRender(({ mesh, canvas, canvasMayDraw }) => {
    if (canvasMayDraw) shadow.updateFrom(mesh.matrixWorld, canvas)
  })
  return null
}

<Surface.Mesh>
  <CardShadowSync shadow={postcardShadow} />
</Surface.Mesh>
```

`postcardShadow` and its `updateFrom` method are application code. Munari calls
this hook after pose updates and world-matrix calculation, before the scene
render. It supplies the actual mesh, canvas, draw camera, and render target. It runs once per render pass, which can be more than once per animation frame. Keep physics in the frame step; use this hook to synchronize companions from its result. A Three.js companion must
already exist in the rendered scene; a separate renderer can draw synchronously
from this callback, as the postcard's light renderer does.

`canvasMayDraw` is permission for the upcoming draw. It differs from
`presentation`, which reports a hold already accepted by the protocol. The
callback also supplies part identity, time, motion progress, and the effective
controller request. It is not a presentation receipt and does not keep an idle
canvas drawing by itself. Low-level pose code can read the same controller with
`readSurfaceFrameState(handle)` from `/advanced`.

React props still express intent. React status subscriptions serve labels and
controls. Coupled drawing reads the controller at frame time so page and scene
commits cannot disagree about pixel ownership. In Home, status subscriptions
stay in the postcard label instead of rerendering the whole site.

[The postcard](apps/lab/src/scenes/home/HomePostcard.tsx) and its
[mesh callback](apps/lab/src/scenes/home/HomeHero.tsx) show the complete wiring.
Its canvas is positioned in the page section. That lets the compositor scroll
card and page together; the manual pose accounts for the actual canvas origin.
The fixed-canvas negative control lagged native content by 12 px. The section
canvas measured no relative drift in the same wheel sequence.

Stable layout and prewarmed resources help, but a blanket freeze would break
live controls, typing, video, resizing, and Gravity's explicit reflow. The
library keeps the declared layout policy. The postcard instrument checks its
known-stable slot and pixel boundary; it does not infer arbitrary position
changes from ResizeObserver, which only reports size changes.

## Inline content and layout reflow

```tsx
<Surface.Root inScene={fallen}>
  <Surface.HTML as="span" layout="reflow">
    <span className="word">Hope</span>
  </Surface.HTML>
  <Surface.Scene>
    <FallingWord />
  </Surface.Scene>
</Surface.Root>
```

`as="span"` keeps the markup valid inside a paragraph. The default `layout="preserve"` reserves the page slot during a handoff. `layout="reflow"` removes that slot only after the canvas presents the content. It restores the slot when a return is requested so the scene can read the destination layout.

`FallingWord` is Gravity's physics-driven group and mesh. Gravity preserves the original word node, removes its space from the paragraph, and restores it on a later click. Its existing canvas-text renderer remains the fallback without HTML capture.

Put visual styles on the HTML content. `pageClassName` and `pageStyle` explicitly style only the page holder, for example to stack alternative views in a grid. The default mesh measures the content rather than an otherwise wider holder.

[Gravity's complete Surface caller](apps/lab/src/scenes/gravity/gravitySurfaces.tsx).

## Content that stays in the scene

```tsx
<SceneSurface.Root name="panel">
  <SceneSurface.HTML size={[width, height]}>
    <Panel />
  </SceneSurface.HTML>
  <SceneSurface.Mesh
    placement="manual"
    geometry={panelGeometry}
    material={panelMaterial}
  />
</SceneSurface.Root>
```

Scene-only HTML has explicit dimensions because there is no page presentation to measure. The Root can be inside its `SurfaceCanvas`, or declared in the page with a mesh contributed to the selected canvas. Use `canvas="id"` when choosing a named host. `SceneSurface.Scene` groups custom contributions declared in the page.

Explode supplies DOM layers it already built:

```tsx
<SceneSurface.Root name={plate.feature.id}>
  <SceneSurface.HTML element={plate.node} size={[plate.width, plate.height]} />
  <SceneSurface.Mesh geometry={plateGeometry} material={plateMaterial} />
</SceneSurface.Root>
```

`plate.node` is a detached element produced by the demo's paint-layer decomposition. Munari owns its capture lifetime and keeps the HTML pointer route. `element` and React children are mutually exclusive.

[Explode](apps/lab/src/scenes/explode/Explode.tsx), [Knobs](apps/lab/src/scenes/knobs/Knobs.tsx), [Workspace](apps/lab/src/scenes/workspace/Workspace.tsx), [Glass](apps/lab/src/scenes/glass/Glass.tsx), [Optics](apps/lab/src/scenes/optics/Optics.tsx), and [Crystal](apps/lab/src/scenes/crystal/Crystal.tsx) exercise these forms.

## Several sources in one shader

```tsx
<Surface.Root surface={transition} inScene={transitioning}>
  <Surface.HTML part="leaving" hidden={showArriving} size={size}>
    <LeavingView />
  </Surface.HTML>
  <Surface.HTML part="arriving" hidden={!showArriving} size={size}>
    <ArrivingView />
  </Surface.HTML>

  <Surface.Scene>
    <Surface.Mesh
      part="leaving"
      sampledParts={['arriving']}
      material={<RefractionMaterial incoming={transition} incomingPart="arriving" drive={drive} tune={tuning} stageW={size[0]} stageH={size[1]} />}
    />
  </Surface.Scene>
</Surface.Root>
```

`transition` comes from `useSurfaceHandle()`. `drive` is the demo's transition clock; `tuning` holds its shader settings; `size` is the measured stage size. The same part name connects HTML, its mesh, and source-specific reads. The material reads its primary texture through `useSurfaceTexture()` and another part through `useSurfaceTextureOf(transition, 'arriving')`.

`sampledParts` declares additional parts displayed by that mesh's shader. The mesh cannot establish readiness until each source has usable pixels. Its actual draw supplies presentation evidence for the declared parts. A missing source holds the whole handoff on the page.

Gallery also needs an invisible input proxy for the incoming view. It uses `presentation="manual"` and disables color and depth writes on that proxy. The visible mesh's `sampledParts` declaration supplies the evidence; the proxy supplies the source-specific raycast and HTML input route.

`hidden` controls a part's page holder and requires an explicit size. Its capture stays available. The application decides which view is revealed after landing. Both views retain their React and DOM instances through the transition and cancellation.

[Refraction](apps/lab/src/scenes/refraction/Refraction.tsx) and [Gallery](apps/lab/src/scenes/gallery/Gallery.tsx) contain the complete shader and pointer wiring. [Dissolve](apps/lab/src/scenes/candidates/CandidateDissolve.tsx) keeps two named parts in stable slots. [Logo](apps/lab/src/scenes/logo/Logo.tsx) coordinates six letter parts under one Root.

## Capture an existing element for another effect

```tsx
const capture = useElementCapture()

return (
  <>
    <article ref={capture.ref}><ArticleContent /></article>
    <SurfaceCanvas>
      <ArticleEffect capture={capture} />
    </SurfaceCanvas>
  </>
)
```

The callback ref reports attachment, replacement, and removal. The original element stays native. Munari maintains an inert visual copy, preserving values and computed appearance without mounting another React instance.

The effect calls `useCaptureFrame(capture)` inside the canvas and reads `frames.get()` in its frame callback. A frame contains the texture, painted dimensions, source identity, revision, and named anchor boxes. Consumers do not dispose the shared texture.

`capture.getBounds()` reads the original element's current viewport rectangle. It is independent of the last painted frame's dimensions. `capture.refresh()` requests an update after an external change not observed through DOM events, mutations, size changes, fonts, styles, or CSS animations. `useCaptureStatus(capture)` reports waiting, ready, unsupported, or error.

[Selection](apps/lab/src/scenes/selection/Selection.tsx) and [Veil](apps/lab/src/scenes/veil/Veil.tsx) use this input. Their native content does not hand its presentation to the scene.

`body` and `html` capture their full scrollable dimensions. The whole-page probe verifies pixels above and below the viewport. `exclude` omits selected subtrees; capture canvases and registered capture consumers are excluded automatically. Capture resolution follows the existing texture-size limit.

This captures element content, not everything composited over it. Standalone SVG roots, iframes, custom elements, shadow roots, CSS masks, and generic embedded media are not promised by the element-copy path. SVG content inside an HTML root is supported. Effects needing specialized inputs can supply authored content or a frame source.

## Author a capture source

```tsx
const capture = useCaptureHandle()

<CaptureContent capture={capture} size={[width, height]}>
  <LetterMarkup words={words} />
</CaptureContent>
```

[Plume](apps/lab/src/scenes/plume/Plume.tsx) captures its letter markup while keeping the textarea native. Capture frames carry the anchor boxes used by its particles.

The same component accepts an already-built detached element:

```tsx
<CaptureContent capture={capture} element={reflectionMarkup} size={size} />
```

[Marble Hand](apps/lab/src/scenes/marble-hand/marbleHandPageCapture.tsx) supplies its specialized page mirror this way. The demo still draws the matching animated background in its reflection; copying a canvas would not reconstruct that rendering policy.

## Video and custom render passes

Genie keeps its original window content and film canvas mounted once. Its separate video decoder keeps playing. Inert visual placeholders copy canvas pixels without creating a second live film publisher. The existing `FrameSurface` composition supplies the required frozen generation and presentation receipts during flight.

Glass retains its custom render passes and the advanced `surfaceManualPresenter` where a final compositor owns the visible draw. The high-level content declarations do not replace these specialized renderers.

[Genie](apps/lab/src/scenes/genie/Genie.tsx) and [Glass's SDF compositor](apps/lab/src/scenes/glass/glassSdf.tsx) are complete callers. Lamp and Rain continue using ordinary HTML and their existing Three.js renderers; neither needs a Surface handoff.

## Hardening checks

The runnable checks in `instruments/` now cover inset/scaled canvases, position-only
slot movement while demand rendering is idle, original DOM/state retention, late
hosts, context loss and recovery, source replacement, native and shared-source
pointer routing, visible preparation selection/focus, and multiple render passes.
The original shared-source route and idle-layout failures have negative controls.
Copy-cost budgets describe their measured Controls/Selection/html/body fixtures;
they do not promise a fixed cost for an arbitrary web page. See decision #42 and
`instruments/api-all-demos/README.md` for commands and measurement limits.
